## example 2

## example 3

- Command Injection (DeviceDiagnostics): Прямая конкатенация адреса в os.system("ping ... " + ip_address) позволяет выполнить сторонний код (например, ; rm -rf ...).
- Блокировка Event Loop (AsyncNetworkServer): Использование time.sleep(1) в асинхронном методе блокирует весь Event Loop. Нужно использовать await asyncio.sleep(1).
- Гонка потоков / Race Condition (ThreadedHeartbeatMonitor): Итерация по DEVICE_STATUS_MAP в отдельном потоке без блокировок (threading.Lock) вызовет ошибку при его изменении из главного потока.
- Утечка памяти (TelemetryDatabaseIngestor): Бесконечное добавление записей в глобальный список TELEMETRY_HISTORY без очистки со временем переполнит ОЗУ.
- Утечка дескрипторов (IoTConfig): Файл открывается вручную без with. При ошибке чтения файл останется открытым.
- Неэффективный I/O (TelemetryDatabaseIngestor): Открытие и закрытие файла лога на каждый полученный пакет создает избыточную нагрузку на диск.
- Хрупкий парсинг (TelemetryPacket): Разбор строки через ручной .split() упадет при малейшем изменении формата сообщения.
- Хардкод учетных данных (IoTConfig): Хранение паролей и абсолютных путей к файлам прямо в коде.

## example 4

- Отсутствие проверки результата malloc: Память выделяется через malloc, но указатель не проверяется на NULL перед использованием, что может привести к сегментации программы при исчерпании памяти.
- Утечка памяти (Memory Leak): В функции reallocate_buffer старый буфер освобождается, но в случае ошибки или при возврате нового указателя теряется контроль над выделенной памятью в вызывающей функции.
- Двойное освобождение (Double Free): В конце демонстрационного кода указатель packet_data освобождается дважды подряд без промежуточного зануления (packet_data = NULL).
- Переполнение буфера (Buffer Overflow): Использование небезопасной функции strcpy и strcat для копирования и объединения строк без проверки размера целевого буфера dest.
- Возврат указателя на локальный стек (Dangling Pointer): Функция get_default_header создает массив header на стеке и возвращает его адрес. После выхода из функции память стека очищается, и возвращенный указатель становится недействительным.
- Уязвимость форматной строки (Format String Vulnerability): Прямая передача пользовательского буфера в printf(payload) вместо безопасного printf("%s", payload).

## example 5

- Использование небезопасной функции gets: Для ввода названия файла и имени товара используется устаревшая функция gets(), которая не ограничивает размер ввода и приводит к переполнению стека.
- Утечка файлового дескриптора: В функции save_database при неудачной попытке выделить память происходит ранний выход из функции (return 0), но открытый файл FILE* f не закрывается через fclose().
- Использование неинициализированных членов структуры: Метод create_item инициализирует только id и price, оставляя массив символов name неинициализированным. При выводе или чтении этой структуры в консоли окажется "мусор" из стека.
- Ошибка "Вне границ массива" (Off-by-one Error): В цикле for функции print_all_items условие i <= count приводит к тому, что на последней итерации программа обращается к несуществующему элементу за пределами массива (выход за границы индекса database[MAX_ITEMS]).
